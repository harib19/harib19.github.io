Aegis

AI-driven timing optimisation for multi-clock RTL

LLMs can suggest useful timing fixes for RTL. On multi-clock designs, though, they also make changes that look fine and aren't: they rearrange a synchronizer or mix up a Gray-coded pointer. Equivalence checking and simulation don't model metastability, so neither catches it. Aegis is meant to get better AI-optimised RTL out of the LLM for multi-clock designs, without those clock-crossing bugs.

Before anything is generated, a structural pass reads the RTL and SDC and locks the clock-crossing logic: synchronizer chains, Gray pointers, reset crossings and clock dividers. Every rewrite the LLM proposes then has to pass these checks:

  1. Lock checkRejected straight away if it modifies a locked region.
  2. Lint & simulationHas to build and behave the same.
  3. Yosys EQYHas to be sequentially equivalent to the original.
  4. CDC re-checkThe structural pass runs again on the new RTL.
  5. Timing per clockOpenSTA reports WNS/TNS for each clock domain separately, so an improvement in one can't hide a regression in another.
4% → 53%candidates passing SEC
0lock violations
40+designs tested

The test designs range from multi-clock FIFOs and handshakes up to AXI/Wishbone bridges, Ethernet and a small SoC. On the SoC, Aegis kept top-level equivalence, reduced area by 3.43%, and fixed the timing in one of the two failing clock domains. The other one is still failing.

An earlier version without the structural checks is also on GitHub.

Other projects

  • Systolic array CNN accelerator

    I defined the micro-architecture and wrote the RTL for a 4×4 output-stationary systolic array (16 DSP48 PEs, INT8 multiply, INT32 accumulate), then integrated it as an AXI4-Lite peripheral on a Zynq-7000. The host side, written in Python and C, handles im2col and DMA.

    The repo also has the model flow: a trained Keras model (MNIST, grayscale CIFAR-10) is exported to memory files for the hardware, along with each layer's intermediate outputs for checking the RTL layer by layer.

    Verilog · Vivado · Zynq2024–25repo →

  • Multi-metric kNN accelerator

    A kNN accelerator on Artix-7 that supports Euclidean, Manhattan, Hamming and cosine distance on one shared ALU, switching metrics with no cycle penalty. Cosine scores are negated so the same min-finding top-K sorter works for all four metrics. Reference vectors are normalised offline, which keeps division and square roots off the FPGA. 2.1× faster than a CPU baseline. Submitted to VLSID 2027.

    Verilog · Artix-72025–26repo →

  • MIPS processors

    A 32-bit single-cycle MIPS core supporting 20+ instructions, with decode, ALU datapath, control unit and memory interface, verified with directed tests on the arithmetic, branch and memory paths.

    A follow-up 6-stage pipelined version (IF, ID, MUL, ADD, MEM, WB) adds forwarding, load-use stalls and flushes on jumps.

    Verilog2024, 2026repo →

EdgeOS

EdgeOS is a startup I'm working on with five others at BITS Goa. It's a platform for deploying AI models on edge devices. You upload a PyTorch, ONNX or TensorFlow model, and it handles the rest: converting and quantising the model for the target (TensorRT, OpenVINO, FP16/INT8), packaging it into a container, pushing it to devices over the air with automatic rollback if an update fails, and monitoring the devices afterwards.

Right now we're focused on NVIDIA Jetson, which most robotics and vision prototypes use. Other NPUs come later.
